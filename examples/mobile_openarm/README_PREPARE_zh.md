# 双臂准备模式

入口：`python -m lerobot.scripts.openarm_prepare`。

需要“一次写入下垂零位、每次先全臂回零再抬 J4”的流程，请使用
[电脑直连双臂 VR 的置零和启动命令](README_VR_REAL_zh.md)。本文的独立准备/回落工具
仍只改变 J4，保留其他关节位置。

故障后从当前位置返回 J1–J7 全零，用 `bash examples/mobile_openarm/run_home.sh --execute`。
两侧夹爪也会同步缓慢闭合到已标定的 `0°`，闭合受阻时保留跟随误差保护。
该独立恢复入口不以 VR 工作限位拒绝读取起点，首目标仍受已有 `10°` 跟随误差保护。
以接管实测位置为反馈边界基准，允许额外
`1°` 向外偏移并随向内恢复收紧边界。目标仍限制在原关节范围内；到位后失能，
不写零位、不再抬肘。使用前退出其他 CAN 控制进程并确认回零路径无遮挡。

使用 `follow.md` 中的全达妙从臂：左臂 `can2`、右臂 `can3`，CAN FD，机器人 ID
`my_bimanual_follower`。这里只控制双臂和夹爪，不连接底盘、升降或主臂。

准备模式保留已经标定好的电机机械零点，以真实反馈为起点，只把两侧第 4 关节缓慢
移动到 `+90°`。其余关节、夹爪保持启动时的实际位置。这是准备姿态，不是重设零点。
默认从 `0°` 到 `90°` 用约 20 秒，采用起点和终点速度、加速度均为零的五次轨迹。
目标角度的速度上限为 `10°/s`，加速度上限为 `5°/s²`；实际运动时间取指定时间与
满足这些限制所需时间的较大值。默认 20 秒轨迹的峰值目标速度约 `8.44°/s`。

## 当前实现范围

流程为：检查标定文件 → 打开 CAN 并读取两臂有效反馈 → 检查静止和关节范围 →
保持当前姿态并上力 → `PREPARING` 缓慢抬肘 → 实测到位并稳定 → `READY` 持续保持。

`READY` 需要全部受控关节实测位置持续在目标 `2°` 内，使用连续 1 秒的新鲜反馈窗口：
每个关节位置最大值与最小值之差不超过 `0.3°`、平均绝对速度不超过 `2°/s`，
且当前速度不超过 `2°/s`。静止时偶发的约 `2.099°/s` 达妙速度反馈不直接重置窗口。
位置误差超出 `2°`、单次速度超过 `5°/s` 或采样间隔超过 `0.2s` 会清空窗口。
不是将正负速度平均抵消，也不能仅靠低速反馈让实际晃动通过。准备和回落共用此判定。
轨迹结束后仍未稳定时每 2 秒输出窗口时长、位置变化和速度信息，方便区分误差与抖动。
首次到位成功后不再使用抬臂开始时的到位截止时间。保持期间短暂越过上述条件会重新
检查稳定状态；连续超出条件 10 秒才报保持故障。`READY` 每次运动只打印一次，
表示该次运动已通过首次到位检查，并不表示此后每一帧反馈都无偏差。
它不是计时到 20 秒就直接宣告成功。默认沿用现有 OpenArm 从臂电机型号、CAN ID、
限位及 `Kp/Kd`；可用 `--support-gain-scale` 显式调整准备模式增益，没有重力补偿。负载导致到位误差较大时会报错，
需要实机调参后才能确定准备时间与保持效果。

启动、返回及故障保持时，对读取的边界位置允许少量偏差：机械臂关节 `0.1°`、
夹爪 `0.5°`。已标定的 J4 在下垂零位允许最低 `−0.5°` 的反馈，保持及返回目标限制为 `0°`；
这不放宽 J4 上限或其他关节容差。例如闭合夹爪反馈为 `+0.208°` 时，日志会提示将保持目标限制为 `0°`。
发给电机的目标仍严格处于原有限位内；超过反馈容差、无效数值仍会报错，不自动重设零点。

独立准备程序仍可单独使用；[电脑直连双臂 VR](README_VR_REAL_zh.md) 已复用其轨迹和
到位判定，在同一电机进程内完成准备、VR 接管和回落。尚未接入系统开机自启动。脚本持有 CAN 时，
不要同时运行 `openarm_follower_hold_zero`、同构遥操作、ROS2 硬件控制或其他电机程序。
VR 入口通过同一控制进程切换状态，保持零位与位置目标连续。

## 使用前提

- 电机已经按模型机械零位标定，且已经核验断电重启后角度基准仍然正确。
- 已有 `my_bimanual_follower_left/right` 标定文件；程序缺少文件时直接报错，不启动交互标定。
  标定文件存在本身不能证明机械零位摆放正确。
- 已确认两侧第 4 关节的正方向对应向上弯肘，`90°` 在实物可用范围内。
- CAN FD 接口按原 `follow.md` 配置完成，机械臂静止、夹爪空载，运动路径有空间。
  第 4 关节反重力运动仍需确认电机跟随能力与实际路径，不能仅据此判断整个过程无碰撞。

## 先预览，不连接硬件

进入已安装此仓库的 LeRobot 环境。本机可用环境为 `lerobot312`；`follow.md` 中旧的
`lerobot310` 名称不代表本机仍有该环境。

```bash
cd /home/xfff67/lerobot
conda activate lerobot312
python -m lerobot.scripts.openarm_prepare
```

默认只打印从 `0°` 开始的参考轨迹，不构造机器人、不打开 CAN、不使能电机。
实际执行时始终使用实测起点，不假定它恰好为零。

读取两臂当前实际角度，不使能、不失能、不发运动目标、不写零点：

```bash
python -m lerobot.scripts.openarm_prepare --read-state
```

电机未使能时仍可反馈角度。若第 4 关节显示 `-7°` 等明显超出范围的值，应核对实物
零位姿态和电机坐标；不能靠扩大容差或启动时自动置零绕过。标定文件中的默认范围
与零偏值并不能证明当前电机零点正确。只读输出保留原始读数，列出全部关节的配置范围。

## 实机准备与保持

完成上述核对后，以下命令会使能并移动两臂：

```bash
python -m lerobot.scripts.openarm_prepare --execute
```

本机当前空载双臂已通过到位判定的参数为：

```bash
python -m lerobot.scripts.openarm_prepare --execute --duration-s 30 --support-gain-scale 4
```

`--support-gain-scale` 默认是 `1`，范围 `1–4`；只将第 1、4、7 关节的 `Kp` 乘以
该值，`Kd` 乘以该值的平方根。取 `4` 时，J1/J4 为 `Kp=200, Kd=2`，J7 为
`Kp=32, Kd=0.4`。其余关节、夹爪及全局从臂配置不变。这组参数只在当前实物和
负载条件下验证过；它减小了持臂误差，并没有消除重力导致的静态误差。

只调试左臂，并将最短运动时间延长到 30 秒：

```bash
python -m lerobot.scripts.openarm_prepare --execute --arm left --duration-s 30
```

可覆盖 `--left-port`、`--right-port`、`--id`、`--elbow-deg`、`--speed-deg-s` 和
`--accel-deg-s2`。单位为度、秒，默认目标 `90°`；启动不会调用 `set_zero_position()`。

## 停止与异常

如果原准备程序已经因故障退出、手臂仍上力，可在确认故障原因已处理、当前反馈正常，
且没有其他控制程序占用 CAN 后，用独立命令放下：

```bash
python -m lerobot.scripts.openarm_prepare --lower --duration-s 30 --support-gain-scale 4
```

此命令面向已经标定的当前双臂：接管时读取真实位置，保持其他关节及夹爪，
只把 J4 缓慢降到 `0°`。到位后打印 `LOWERED: torque disabled` 并退出，
不会重新抬回接管时的姿态，也不会写零点。应使用与上一个保持程序相同的增益。
独立接管不能读取上一个进程的目标，开始接管时可能有短暂的位置调整。
回落中按 `Ctrl+C` 会停止轨迹并保留力矩，不会立即失能；检查失败同样不切断已有力矩。
`--lower`、`--execute`、`--read-state` 互斥；不要在准备程序仍运行时另开回落程序，
此时应在原程序中按 `Ctrl+C`，以连续目标回落。

- 正常收到 `Ctrl+C` 或 `SIGTERM`：停止抬升/保持，目标从上一条指令连续过渡回启动姿态，
  到位并稳定后关闭力矩。停止不是立即退出，默认需要约 20 秒及稳定时间。
  回落起始目标不直接改成受重力影响的滞后实测位置，避免切换时产生目标跳变。
- 任一电机没有有效反馈或反馈超过 `0.2 s`、控制循环停顿超过 `0.2 s`、跟随误差超过
  `10°`、轨迹结束后 10 秒仍未首次稳定，或首次到位后持续超出保持条件 10 秒：
  进入故障处理，不继续抬升。反馈失效和超过 `10°` 的跟随误差不会等待 10 秒。
- 上力后发生故障：若还能取得有效反馈，尝试发送实测位置保持目标；否则不再发送新运动
  目标。退出时保留力矩，不主动让抬起的手臂自由下落。总线故障时软件无法保证保持成功，
  电机自身的超时配置也可能改变保持行为；需要现场支撑机械臂并检查。
- 物理急停独立于上述软件流程。不要用强制杀进程或直接断电代替正常缓慢放下。

将来接入开机启动时，应等待电机供电与 CAN 接口就绪；故障后不要自动无限重试。
停止服务应给缓慢返回留足时间。当前没有安装或启用任何自启动服务。

操作者确认机械臂自然下垂、两侧夹爪完全闭合后，只校正了右臂第 4 关节及左右夹爪的

这次验证了通信、零点校正和缓慢抬落链路，原始增益下约有 `7°` 持臂误差。

## 同日增益复测

分析还发现 J1/J7 保持位置有约 `4–5°` 偏差，因此只对 J1/J4/J7 调整准备模式增益。
倍率 `2` 时双肘稳定约 `86.52°/86.26°`，仍未达到 `2°` 标准；该轮已正常返回并失能。
这轮也发现从实测位置启动回落会改变目标，已修正为从上一条指令连续回落。

倍率 `4` 的 30 秒抬臂测试中，双肘稳定采样约 `88.14°/88.14°`，最大位置误差约
`1.86°`，程序实际进入了 `READY`，没有放宽 `2°` 到位标准。该结果是短时空载测试，
不是精确无误差的 `90°`，也未验证长期保持、带载、断电重启零位或 VR 接管。
测试在第 36 秒开始正常回落，随后返回起始姿态并关闭力矩，程序正常退出。
当前仍未部署开机自启动。相关无硬件回归测试共 35 项通过。

发现终点浮点误差会生成约 `-4e-14°` 的目标，已修正为精确端点并将插值限制在起终点
