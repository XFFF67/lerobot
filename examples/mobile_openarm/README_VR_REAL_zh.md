# 电脑直连双臂、底盘与升降的 VR 控制

使用当前电脑的 `can2`（左臂）和 `can3`（右臂），不需要中间小电脑。
全达妙双臂和夹爪走 CAN FD；提供 `--mobile-port` 时，底盘与升降通过 CH343 串口接入同一个
VR 控制循环。左手柄 X 键用于双臂复位；右摇杆按下切换底盘平移/自转构型，A/B/Y 不控制底盘。

链路：Quest 浏览器 → 本机 HTTPS/WebSocket → 本机 Telegrip 数据 → OpenArm IK →
同一电脑上的电机控制进程 → CAN FD 双臂 + CH343/C板底盘和升降。双臂IK与移动映射读取
同一帧手柄快照，联合目标通过私有本地套接字送回唯一硬件进程；不再运行第二个移动VR订阅器。
网页、手柄相对位姿、松握把保持、重新握持
建立参考点的方式复用 HEI/已有仿真入口；不使用 HEI 的六关节映射或夹爪弧度端点。

## 一次设置下垂零位

将双臂 J1–J7 摆到确认的自然下垂机械零位，停止其他控制进程，然后执行一次：

```bash
bash examples/mobile_openarm/run_set_zero.sh --execute
```

该命令沿用 hei-rebot 零位工具的“失能 → 写电机零点 → 读取反馈”方式，适配此处
7 关节双臂和 CAN FD。先确认反馈静止，再失能 J1–J7、再次等待静止，逐电机发送
置零命令，最后要求连续 0.3 秒读回在 `±0.5°` 内。完成时打印 `ZERO SET`，电机保持失能。
默认不改夹爪。若也要重设夹爪零点，先将两侧夹爪手动闭合，再加 `--include-grippers`。
可用 `--arm left` 或 `--arm right` 只设置一侧。不带 `--execute` 只打印说明，不连接 CAN。

此命令把摆放的物理姿态定义为零位，不是运动回零；仅在首次设置或重新标定时使用。
它不检查机械安装方向，也不自动判断下垂姿态。零位写入使用电机 `SET_ZERO` 命令，
不是启动时保存一帧临时目标；断电后的保留情况仍需在本机电机固件上验证。
已有正确零位时无需重写；日常只运行下面的启动命令。

## 日常启动：先回零，再准备

先确认没有准备模式、回落、同构遥操作或 ROS2 硬件程序同时控制这两路 CAN。
机械臂应已标定且静止，反馈在允许范围内，回零路径无遮挡；本入口不会设置零点。
启动时 J1–J7 会从当前实测位置缓慢回到固定的 `0°`，不再把启动位置当成返回目标，
也不再仅因 J4 大于 `10°` 拒绝启动。通信或限位故障仍需先处理再启动。

已标定的 J4 在自然下垂时允许 `−0.5°` 以内的负向零位反馈偏差，例如 `−0.164°`。
程序将此时 J4 初始保持目标限制为 `0°`，随后完成全臂回零，再把 J4 抬到 `90°`。
低于 `−0.5°` 仍拒绝启动；J4 上限、其他关节容差和目标指令限位保持不变。

终端 A：启动已有网页服务。当前电脑 Wi-Fi 地址为 `192.168.204.176`，换网后需更新：

```bash
cd /home/xfff67/lerobot
bash examples/mobile_openarm/run_vr_server.sh --hostname 192.168.204.176
```

Quest 与电脑连同一局域网，在头显浏览器打开：

```text
https://192.168.204.176:8443/real
```

确认本地证书提示后点击 `Start VR`。`/real` 显示双臂真机操作说明；它与仿真网页
共享输入协议。机械臂是否启动由终端 B 决定，网页连接成功不表示电机已准备好。
已有旧网页服务需要重启一次才能识别 `/real` 路由。不要另开第二个占用 8443/5567 的服务。

终端 B：

```bash
cd /home/xfff67/lerobot
bash examples/mobile_openarm/run_vr_real.sh --execute --viewer
```

整机联合控制使用C板实际设备路径，例如当前CH343枚举为 `/dev/ttyACM0` 时：

```bash
bash examples/mobile_openarm/run_vr_real.sh --execute --viewer \
  --mobile-port /dev/ttyACM0
```

推荐将 `/dev/ttyACM0` 换成稳定的 `/dev/serial/by-id/...` 路径。联合模式下不要同时启动
`run_vr_mobile.sh`，否则它会与本进程争用串口；后者只保留作底盘/升降独立诊断。

程序自动执行：

1. 加载并检查模型/IK，再连接 CAN；连续 0.2 秒确认静止，最多等待 3 秒。
2. 在实测位置上力，进入 `HOMING`：J1–J7 默认用 10 秒发送到已标定的 `0°`，夹爪保持启动位置。
   轨迹结束后直接进入 `PREPARING`，用约 20 秒把两侧 J4抬到 `90°`。
   其他关节目标仍为 `0°`，两个阶段连续保持力矩，不重连、不写零位。
3. 回零和准备按设定时间完成后直接进入 `VR_READY`，不再增加实测 `±2°` 到位和1秒稳定门槛。
   CAN反馈新鲜度、关节指令限位和原有 `10°` 跟随误差故障线仍然生效。
4. 先松开握把，再握住对应侧手柄控制。没有 VR 输入时双臂保持准备目标，底盘和升降发送停车帧。
   启动时先检查并独占C板串口、发送停车帧，再打开双臂CAN；回零和抬肘阶段不发送运动命令。
   这样串口缺失或无法打开会在机械臂运动前立即报错。
5. 先放稳物体并用扳机张开夹爪释放，再在电脑终端按 `Ctrl+C`，从最后发送的目标连续回到
   J1–J7 固定下垂零位，夹爪回到启动位置，至少 30 秒后到位失能。返回流程不用于带物体自动回落。

`--viewer` 显示实测关节的 MuJoCo 示意窗口，关闭窗口也会启动正常回落；去掉该参数
可无窗口运行。网页退出 XR、摘下头显或松开握把只暂停跟随，保持上力，不自动失能。

**双臂复位：松开两侧握把，再按一下左手柄 X 键。** 两臂其余关节回 `0°`、J4 回 `90°`，
夹爪保持当前开合目标，不重新写零位，不先经过下垂姿态。终端显示 `VR_RESET`，
沿平滑轨迹以不超过 `5°/s` 的关节速度返回；时长至少为 `--prepare-duration-s`（默认 20 秒），
较大位移会自动延长。到位并稳定后显示 `VR_RESET_READY`，松开再握即可继续跟随。
复位期间保持两侧手柄可追踪、握把松开；握住任一握把、失去追踪或断流会中止复位并保持最后目标，
需要重新按 X 才会重试。长按 X 不会重复触发。该动作是回准备姿态，与 `run_home.sh` 的下垂回零不同。

网页 WebSocket 短暂断线时保留 XR 画面并自动重连，画面提示控制暂停；重连后必须松开再握。
网页诊断会保留最近一次断线代码及原因、XR 会话结束来源。若仍自动退回普通网页，
请查看该诊断和 VR 网页服务终端的 `[VR browser]` 日志；头显主动结束 XR 的具体原因可能不会由浏览器提供。

不带 `--execute` 只打印流程，不打开 CAN，也不启动 IK：

```bash
bash examples/mobile_openarm/run_vr_real.sh
```

## 手柄与参数

握住左/右握把：对应手臂跟随相对平移和旋转；松开即保持当前目标，可重新选取舒服的握持位置。
握把按住时，按住扳机以全开为目标，松开扳机以闭合为目标；不是点击切换模式。
夹爪电机目标范围为 `[-65°, 0°]`，独立限速 `35°/s`，完整单程约 2 秒。
松开侧面握把会暂停夹爪和对应手臂。

移动控制与双臂共用同一手柄数据：左 Grip + 左摇杆上下控制升降；右 Grip + 右摇杆上下控制
底盘前后；右 Grip 按住且左 Grip 松开时，左摇杆左右调整平移轮向。右 Grip + 按下右摇杆
只切换平移/自转构型；进入自转构型后，右摇杆左右才控制旋转，回中停止旋转但保持构型，
再次按下右摇杆返回平移并恢复此前保留的轮向。平移轮向范围为 `-90°～90°`。松开右 Grip
只让速度归零，保持当前轮向和平移／自转构型；正在切换的轮组继续执行到最后目标，不自动回正。
B/Y不控制底盘。

程序打开C板串口后，在双臂归零和准备期间持续发送中立帧：底盘进入平移模式并以零速度
回到 `0°` 轮向，同时保持串口在线。升降在首次按住左Grip时从实测当前位置接管，不会自动
上升到最高零位。进入VR控制后，短暂丢失手柄数据只会令速度归零并保持最后轮向和构型。

C板还会每10 ms回传12字节状态。真机控制和独立移动桥接都会持续排空这些回传字节，避免
CH343/Linux接收队列堆满后反向阻塞C板串口；双臂准备及退出回零阶段也保持该串口收发节拍。

默认底盘平移上限 `0.05 m/s`、自转标量 `0.005`、升降电机速度 `0.05 rad/s`。可用
`--mobile-speed`、`--mobile-spin`、`--lift-speed` 调整；上限分别为 `0.1`、`0.01`、`0.1`。
方向可用 `--drive-sign`、`--steer-sign`、`--spin-sign`、`--lift-sign` 在 `-1/1` 之间调整。
闭合时电机进程根据新鲜反馈限制目标：最多领先实测角度 `5°`，避免物体阻挡时仍把目标
推向全闭、不断累积跟随误差。例如实测停在 `-30°` 时，闭合目标最多到 `-25°`。
这利用现有位置控制维持有限的闭合预紧，不提高夹爪增益；不是经过标定的夹持力控制，
也不能区分正常接触和机械卡滞。空载仍会继续闭合到 `0°`，按住扳机可重新张开到 `-65°`。
夹爪独立限速、握把许可、反馈超时及 `10°` 跟随误差保护仍生效；张开受阻仍会故障停止。
每 5 秒日志显示夹爪实测值/目标值，故障信息包含关节实测值、目标值和误差。
IK 中的手指平移只是可视化映射，不是毫米与电机角度的实测标定。

复用当前模型的手部坐标映射：向前对应模型 `−X`，向左对应 `−Y`，向上对应 `+Z`。
关节 1–7 使用同名电机与模型关节、度转弧度、无额外符号翻转或偏移。J4 正向抬升已经
真机验证；其余关节的模型方向与实际安装、TCP 估计位置还需首次小幅单臂操作核对。
默认 TCP 是仿真所用的指尖中心，几何估计并非实测工具标定。

默认真机参数：手柄位移倍率 `1.0`，末端目标平移限速 `0.20 m/s`、旋转 `60°/s`，
关节指令限速 `30°/s`，夹爪独立限速 `35°/s`。可用 `--gripper-speed-deg-s 25` 放慢夹爪。
VR 关节起步加速度默认 `120°/s²`，目标滤波时间常数为原来的 `0.65` 倍，约 `12–36 ms`。
模型链路对照中，准备姿态下 3 cm 收回阶跃达到 90% 位移约从 0.40 秒缩短至 0.36 秒；
这不包含实物负载、网络和电机响应。恢复此前响应参数可加
`--joint-acceleration-deg-s2 90 --vr-filter-scale 1 --arm-linear-speed-m-s 0.16 --arm-angular-speed-deg-s 50`。
夹爪增益倍率默认 `1.5`，当前配置对应 `Kp=12`、`Kd≈0.245`；需要原力度可用 `--gripper-gain-scale 1`。
这是位置控制增益调整，实际夹持力未经测力标定；遇阻关闭仍限制为反馈前方最多 `5°`，不累积到闭合端点。
IK 求解在实机关节限位内留出 `3°` 余量，并与模型限位求交集；例如 J6 目标限制在 `[-37°, 37°]`。
启动已保持的角度若在余量区内，允许保持或向内移动，不允许继续向外；夹爪保持完整标定行程。
电机进程再次检查限位和指令速度。
真机 IK 默认把 J2 的关节增量惩罚设为其他关节的 `8` 倍，优先寻找 J2 少摆动的冗余解，
并把朝机身内收方向的代价提高到 `32` 倍（左J2正向、右J2负向），优先保持或向外选解。
J2 仍参与求解；这不是固定 J2，也不是把摆幅除以 8。
可用 `--ik-j2-motion-weight 4` 减弱偏好，`--ik-j2-motion-weight 1` 恢复原来的等权选解（范围 1–32）。
内收方向的 `32` 倍惩罚固定在真机IK程序中，不需要启动参数。
末端位置/朝向目标和关节硬限位保持原有定义；遇到需要 J2 配合的姿态仍会移动 J2。
无硬件模型对照中，从双侧 J2 为 ∓20°、J3 为 ±30°、J4 为 90° 的姿态向身体收回 15 cm，
J2 最大变化约从 `9.54°` 降为 `3.66°`，最终末端位置误差小于 1 mm、朝向误差小于 0.5°。
这是指定轨迹的模型结果，实际摆幅仍取决于起始姿态和手柄朝向。
向外运动进入上述目标边界前 `8°` 时逐渐减速，并用反馈速度预测前方 `0.1 s` 的位移；
越靠近边界，允许的向外速度越小，向内离开该边界不受这侧减速约束。
电机因边界阻止继续向外运动或 IK 无法跟随时，手柄参考会对齐到已接受目标的末端姿态，
丢弃受阻的位移和旋转积累；新一帧反向动作仍可生效。普通关节减速和 IK 步长限速保留可达目标以便追上。
启动及整个 VR 阶段沿用已测试的增益倍率 `4`：J1/J4 `Kp=200, Kd=2`，J7 `Kp=32, Kd=0.4`。

例如准备更慢或手柄动作更小：

```bash
bash examples/mobile_openarm/run_vr_real.sh --execute --viewer \
  --home-duration-s 10 --prepare-duration-s 30 --lower-duration-s 30 \
  --vr-position-scale 0.3 --joint-speed-deg-s 10
```

电机进程始终保持 CAN 连接，准备到 VR 的切换不重新使能、不置零、不把目标突然换成
受重力影响的滞后反馈。IK 从上一次实际发送的目标继续求解，窗口独立显示真实反馈。
本控制没有动力学重力补偿或碰撞检测，不应将 MuJoCo 示意窗口当作实物碰撞保护。

## 断流、退出和故障恢复

- VR 单侧输入超过 0.3 秒失效、追踪跳变或松开握把，该侧停止更新目标；恢复后需先松再握。
- 联合移动控制收到陈旧/无效联合目标时立即发送9字节停车帧；正常退出VR阶段时先停车，
  再执行双臂下垂回零。串口关闭前再次发送停车帧。
- IK 指令或其依据的状态超过 0.2 秒，电机进程保持最后目标并重置握持许可，防止处理旧输入。
- VR 阶段关节反馈越过原限位但不超过 1° 时，进入 `Joint-limit recovery`：该关节禁止继续向外，
  允许握持手柄以不超过 `5°/s` 的关节指令速度向内恢复，另一侧继续操作，不必松开再握。
  不再因轻微越界持续 0.5 秒退出；回到原限位内至少 `0.5°` 后退出恢复状态。
  这不是自动回零。松开握把或输入断流仍保持已有目标；单次越界超过 1° 仍报错保留力矩。
  启动检查和目标指令没有放宽到限位外。
- CAN 反馈缺失/超时、循环停顿、跟随误差超过 10°、指令越界等故障：退出并保留最后目标和已有力矩，
  不自动重试或直接切断支撑。故障后需现场确认手臂和通信状态。
- VR 阶段 IK 子进程退出或显示窗口关闭，在电机反馈仍正常时执行正常返回；准备/VR 阶段 `Ctrl+C` 同样返回。
- 初始 `HOMING` 阶段按 `Ctrl+C` 则停在最后目标并保留力矩，不再继续回零或抬肘；现场处理后再启动。
- 正常返回阶段要等待完成，不要强制杀进程来代替回落。

如果控制进程已退出，需要从当前位置返回已设置的全臂下垂零位，确认无负载且回零路径
无遮挡后运行独立回零命令（无需 VR 网页或 IK）：

```bash
bash examples/mobile_openarm/run_home.sh --execute
```

双臂 J1–J7 同时限速回到 `0°`，两侧夹爪沿同一平滑轨迹缓慢闭合到已标定的 `0°`，
全部到位并稳定后失能；夹爪闭合受阻仍会触发跟随误差保护。不会重写零点，
也不会继续抬 J4 到 `90°`。默认至少 `30s`，速度不超过 `10°/s`、加速度不超过 `5°/s²`。
可加 `--duration-s 45` 放慢，或用 `--arm right` / `--arm left` 只回一侧。
不带 `--execute` 仅显示流程，不连接 CAN。

启动时读取真实静止姿态，不再因机械臂读数越过 VR 工作限位或超过固定 `3°` 门槛而拒绝读取。
例如 `right_joint_3=-88.444°` 时，首个目标限制到 `−85°`，之后沿回零轨迹向限位内移动。
使能前仍检查该首目标与实测位置的误差不超过已有的 `10°` 跟随误差阈值；这与运动中
使用同一标准，避免将严重不一致的反馈直接变成突跳目标。
接管后的反馈边界以启动实测位置和原工作范围为基准，允许额外 `1°` 的向外偏移；
不再把固定的 `−86°` 当作整个恢复过程的硬边界。实测位置向内恢复后，该边界随之收紧，
不会随着向外漂移而放宽。例：启动读数 `−85.559°` 时，下边界为 `−86.559°`，
允许日志中的短时 `−86.433°`；回到原范围后，下边界收紧为 `−86°`。
这仅改变独立恢复时的反馈判定，发送的所有目标仍在原有限位内，不改变 VR 阶段的保护。
首目标跟随误差过大、继续向外偏移超过允许量、反馈缺失、跟随误差或无法到位仍停止；中途 `Ctrl+C` 保留最后目标和力矩，
只有确认到位才失能。关节插值没有避障规划，不能把“任意起点”理解为可以穿过障碍物。
不要在另一个控制进程仍占用 CAN 时执行；故障恢复时不要使用 `run_set_zero.sh` 重写零位。

如果只需要降低双肘、保持其余关节位置，仍可用原来的独立回落命令：

```bash
conda activate lerobot312
python -m lerobot.scripts.openarm_prepare --lower --duration-s 30 --support-gain-scale 4
```

这会保持其他关节，仅把双肘降到机械零位附近，再失能。不要在 VR 控制进程仍运行时执行。
