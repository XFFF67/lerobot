# MJCF 移动双臂键盘 / VR 控制

为双 7 自由度 OpenArm 提供独立的键盘仿真框架，不会连接真机。
代码和模型均放在 LeRobot 的 `examples/mobile_openarm/`：

**Meta Quest VR 控制已提供独立入口，见 [VR 启动与手柄教程](README_VR_zh.md)。**
VR 复用这里的双臂逆解、闭环升降、物理底盘和桌面抓取；原键盘入口继续独立使用。

```text
mobile_openarm/
├── run_keyboard_sim.sh
├── keyboard_sim.py
├── pinocchio_ik.py             # Pinocchio + CasADi/IPOPT 末端逆解
├── torso_lift.py               # 躯干闭环升降联动
├── chassis_physics.py          # 可选的四轮摩擦、斜连杆与磁吸动力学
├── grasp_physics.py            # 桌面、物体、双臂接触与夹持力设置
├── mujoco_scene.py             # HEI 风格场景与默认视角
├── check_keyboard_sim.py
├── check_chassis_physics.py
├── check_grasp_physics.py
└── model/
    ├── mjcf1/
    │   ├── robot.xml                 # 完整机器人模型入口
    │   ├── openarm_v1_*.xml          # 双臂、关节、约束及资源定义
    │   ├── gripper_camera_assets.xml # 夹爪相机外观资源定义
    │   └── meshes/                   # 底盘、躯干、双臂、夹爪等网格资源
    └── scene_assets/ycb_011_banana/   # 香蕉网格、纹理、来源与许可证说明
```

模型从原 `/home/xfff67/mjcf1/` 复制，保留 XML 和网格的相对路径。
原目录保留作备份；默认启动只读取这里的模型副本，不依赖原目录。

## 启动

只需一个终端。脚本默认自动激活已有的 `hei-rebot-vr` Conda 环境：

```bash
cd /home/xfff67/lerobot/examples/mobile_openarm
./run_keyboard_sim.sh
```

也可从 LeRobot 根目录运行 `bash examples/mobile_openarm/run_keyboard_sim.sh`。
省略 `--mjcf` 时加载脚本旁的 `model/mjcf1/robot.xml`，与终端当前目录无关。
指定其他模型可用 `./run_keyboard_sim.sh --mjcf /路径/robot.xml`。
依赖 `mujoco`、`numpy`、`glfw`、`pinocchio`（含 CasADi 绑定）和 `casadi`。
本机已验证的环境为 Python 3.10、Pinocchio 3.9.0、CasADi 3.7.0、MuJoCo 3.5.0。
在新电脑上可从本目录创建环境：

```bash
conda env create -f environment.yml
```

环境名称可通过 `MOBILE_OPENARM_CONDA_ENV=环境名 ./run_keyboard_sim.sh` 修改。
也可用 `PYTHON=/环境路径/bin/python ./run_keyboard_sim.sh` 明确指定解释器。
启动脚本清除 `LD_LIBRARY_PATH`，避免外部动态库覆盖环境中的依赖。
启动时应看到 `IK: Pinocchio + CasADi / IPOPT (7 joints per arm)`；依赖缺失会报错，
不会自动退回旧的 MuJoCo Jacobian 求解器。

新入口替代原 `python3 -m mujoco.viewer --mjcf=...` 命令，增加键盘控制。
它使用 MuJoCo 渲染与 GLFW 窗口；没有原生 viewer 的参数编辑侧栏。
键盘只在这个窗口获得焦点时生效，失去焦点会清除运动键并取消自动复位。

## HEI 风格仿真场景

默认启动会加载以下环境，尺寸和配色参照 HEI ReBot Lift：

- 浅灰方格地面、渐变天空、顶部主光与前侧补光。
- 橙色 `4 × 4 m` 区域边框、青色 `0.7 × 0.7 m` 起始位置框。
- 地面原点投影处的 XYZ 标记（X 红、Y 绿、Z 蓝）。
- `0.72 × 0.93 m` 操作桌（桌面按 HEI 原尺寸等比例缩至 75%），桌面距离地面 `0.70 m`。
- 红、绿、蓝三个边长 `6 cm` 方块，以及带真实纹理的 YCB 香蕉。

适配本模型时，地面设为世界坐标 `Z = -0.264 m`，与轮底贴合；机器人原始坐标保持不变。
桌子及物体相对 HEI 布局绕 Z 轴旋转 180°，桌子中心在 `X = -0.80 m`，对应当前 `W` 的方向。
靠近机器人的桌边保持在 `X = -0.44 m`；桌腿和物体间距随桌面缩放，方块边长为 6 cm，香蕉保持原尺寸。
三个方块和香蕉在缩放布局的基础上，均沿世界 +X 向机器人靠近 5 cm。
环境通过 `mujoco_scene.py` 在内存中加入，不改写原始 `robot.xml`。香蕉资源保存在项目中，启动无需联网。
场景尺寸和来源见 [scene_assets/README.md](model/scene_assets/README.md)。

默认运动学预览中的物体保持静态；加 `--chassis-physics` 后启用桌面碰撞、自由物体和摩擦抓取。
如需仅显示机器人，从本目录运行：

```bash
./run_keyboard_sim.sh --plain-scene
```

## 按键

默认选择左臂，单按 `3` 不会使机器人移动；选择后需要按住运动键。
若曾用 `Tab` 进入 JOINT 模式，再按 `3/4` 会明确切回 TCP 模式。
以 MJCF 的 `openarm_left_*` / `openarm_right_*` 命名为准。
当前模型这些名字的左右关系不等同于屏幕左右。

| 按键 | 功能 |
| --- | --- |
| `1` | 选择底盘；需以 `--chassis-physics` 启用下述动力学模式 |
| `2` | 选择躯干升降模式，按住 `I / K` 上升 / 下降 |
| `3 / 4` | 选择左臂 / 右臂，并切回 TCP 末端控制 |
| `W / S` | TCP 沿模型 base_link 的 −X / +X 平移 |
| `A / D` | TCP 沿模型 base_link 的 −Y / +Y 平移 |
| `R / F` | TCP 沿模型 base_link 的 +Z / −Z 平移 |
| `U/J`、`I/K`、`O/L` | 机械臂模式：TCP 绕同一组固定轴 ±Rx、±Ry、±Rz 旋转 |
| 按住 `Z / X` | 当前夹爪逐渐张开 / 闭合；松开保持开度 |
| 按住 `Shift` | 精细控制，默认 25% 速度 |
| `Space` | 清除旧运动输入，取消双臂自动复位；按住时禁止运动 |
| `5 / 6` | 左臂 / 右臂缓慢回到 MJCF 的 home 姿态；夹爪保持 |
| `Backspace` | 完整恢复模型 home keyframe，没有 home 时恢复 qpos0 |
| `V` | 显示/隐藏 body 坐标系 |
| `C` | 显示/隐藏几何接触点；不是物理抓取力反馈 |
| `Tab` | 在 TCP 控制和单关节点动之间切换 |
| `[` / `]` | 选择上一个 / 下一个机械臂关节（1–7） |
| `- / =` | 单关节模式：减小 / 增大所选关节角度 |
| `Esc` | 退出 |

鼠标左键拖动旋转视角，右键拖动平移，滚轮缩放。窗口不显示操作提示、状态文字或 TCP 文字标签。
键位说明仍在启动终端输出。切换控制对象时清除旧按键；复位期间重新输入该臂运动会取消复位。
松开运动键后立即保持当前运动学姿态，没有积累的远端目标继续追踪。

TCP 控制使用 **base_link 固定轴**，不是工具自身轴，也不是屏幕方向。
此 CAD 模型的“前方”没有经过真机标定，因此不把 +X 强行标记为实机前进方向。

### 四轮摩擦驱动与磁吸模式切换（实验功能）

仍然只需一个终端，从本目录启动：

```bash
./run_keyboard_sim.sh --chassis-physics
```

按 `1` 选择底盘：

| 按键 | 底盘模式下的功能 |
| --- | --- |
| `T` | 切到平移并回正平行轮组；滑块在前端磁吸位置 |
| `G` | 从当前平移轮角直接切到自转：两组连杆约 +53° / −53°，滑块到后端磁吸位置 |
| 按住 `W / S` | 平移模式下沿当前轮向前进 / 后退；不会自动回正 |
| 按住 `A / D` | 平移模式：减小 / 增大轮组转角，范围约 −90°～+90°；自转模式：绕 +Z / −Z 转动 |
| `Shift` | 慢速移动；切换的驱动阶段也减速 |
| `Space` | 取消切换并制动；按住期间不接受新的切换命令 |
| `Backspace` | 回到完整初始姿态和前端平移模式 |

切换需要几秒，终端显示 `magnetic endpoint reached` 后才能移动或自转。
切换过程中移动键不生效；切换控制对象或窗口失焦会取消自动切换。
取消或超时后，重新按 `T/G` 发起切换，必要时按 `Backspace` 复位。
窗口仍不显示任何文字提示。`2` 升降、`3/4` 双臂的键位保留。

平移模式下，`A/D` 只调整四轮共同转角，不发送平移速度命令；目标角速度为 30°/s，
`Shift` 可慢调。松开后保留所选轮向，`W/S` 沿该轮向前进/后退，绝不会因按 `W/S` 自动回正。
轮向为 0° 时前后移动，接近 ±90° 时左右移动，中间角度对应斜向移动；车架保持朝向。
`W/S` 与 `A/D` 可以同时按，轮向误差超过 3° 时先等待轮组跟上；相反按键相互抵消。
转角限于原模型允许的约 −90°～+90°（限位内留 0.001 rad 余量）。
松开移动键后减速；`Space` 或失焦取消未完成的转向。按 `T` 自动回正；按 `G` 从当前实际轮角直接切换自转构型，不要求先回到 0°。
平移轮向在约 −90°～+90° 内均可请求自转，摆轮途中也可按 `G`；切换时清除原有移动/转向按键。
四轮仍通过地面摩擦推动连杆和滑块，不瞬间设置轮角；轮组到达约 ±53° 且滑块后端就位后才允许自转。
平行轮组转向过程中，滑块仍在前端磁吸位置，不能把转向到约 90° 与后端约 53° 自转构型混淆。
朝向保持通过四轮差速反馈实现，未固定车架自由关节；接触求解与轮胎滑动仍会产生小幅偏航。
`A/D` 不发送平移速度，但被动连杆摆动和接触运动仍可能使车架产生数厘米位移，尚非严格原地摆轮。

**机构沿用原有两根斜连杆，没有添加车架直线导轨或转向电机。**
模型中的 `link_014_joint` 保持 `0～0.13675 m`，`link_015_joint` 保持
`−0.13675～0 m`，不会为了凑足 53° 扩大行程。两处滑动副的位移不应直接相加当作中央滑块行程。
两组轮子分别向相反方向转动；53° 是连杆编码器参考值，并不意味着任意两个轮向都严格成 90°。

实现包含：

- `base_link` 的自由关节、重力、四个连续旋转轮轴、轮胎与地面的摩擦接触，使用 `mj_step` 积分。
- 轮胎接触用与网格尺寸匹配的圆柱代理（半径约 98.4 mm），模型外观保持不变。
- 只向四个轮轴发送有限力矩，通过地面摩擦推动被动连杆。编码器读取实际关节角，不直接写入底盘位姿或连杆角度。
- 两个滑动副上始终存在朝向两端的等效磁吸力，并有被动阻尼。切换命令不启停磁吸、不焊死滑块。
- 模式切换到位同时检查滑块距离、四轮角度及转动速度；默认角度容差 1.5°、端点距离容差 1 mm。
  MuJoCo 的软限位允许微小数值越界，默认测试在 0.5 mm 内检查。
- 导出模型保留了 `link_013_joint` 的额外被动同轴转动自由度。切换时四轮共同驱动；
  磁吸就位过程中按两组轮子的角度差协同纠偏，末段同时计算四轮残差，不再刹住三个轮子只补转第四轮。
  四轮的方向、速度可以不同，靠实际接触推进连杆，不将轮角硬设成完全同步。
  没有锁死这个关节。平移期间检查轮组是否保持平行，自转期间检查约 53° 构型；
  脱离端点或轮组角度关系偏离过大时，停止行驶并提示重新停靠。

默认平移速度 `0.10 m/s`、自转速度 `0.10 rad/s`，轮速逐渐变化以减小对磁吸的冲击。
这些速度是目标值，实际运动受接触和滑动影响。松键会减速制动，车体不会瞬间冻结。

磁吸采用滑动副上的**等效双稳态力模型**，不是磁场有限元计算，也没有实测标定。
当前轮胎摩擦系数为 1.0、电机力矩上限为 4 N·m、每个滑动副的等效端点吸力为 16 N、
吸力衰减距离为 10 mm；这组数值用于演示，不能据此推断真机磁铁吸力或切换扭矩。
被动关节另有数值阻尼与近似轴承摩擦。可调整的参数示例：

```bash
./run_keyboard_sim.sh --chassis-physics \
  --tire-friction 1.0 --wheel-torque-nm 4 \
  --magnet-force-n 16 --magnet-distance-m 0.01
```

磁吸过强或地面牵引不足时，切换可能失败；15 秒未到位会停止，不会强行改写关节角。
物理模式同时启用桌面、桌腿、四个物体、双臂和夹爪原有碰撞网格之间的环境接触。
装饰坐标轴、地面边框、相机外观与机器人自身之间的碰撞保持关闭。
双臂和抬升使用位置目标伺服及理想上身补偿；抬升仍由原闭环求解器产生目标，
手臂继续使用 Pinocchio + CasADi/IPOPT。接触参数用于仿真演示，尚未按实物标定。
原始 XML 均不改写；省略 `--chassis-physics` 仍使用原来的运动学预览。

不打开窗口的动力学自检：

```bash
./run_keyboard_sim.sh --chassis-physics --headless-check
```

自检覆盖前后移动、独立转向与角度保持、转向后的横移及车架偏航、−90°～+90° 每隔 30° 及摆轮途中直接切自转、四轮末段共同校正和同组轮角差、双向自转、磁吸位置往返切换、
行程和力矩界限、底盘转动后的抬升与双臂控制、
停止及失焦、切换超时，并关闭接触验证空转轮子不能完成切换。默认参数用于回归；修改物理参数后不保证仍能通过。

### 桌面抓取

启动物理模式即可抓取，无需额外终端：

```bash
./run_keyboard_sim.sh --chassis-physics
```

1. 必要时按 `1`，用底盘靠近物体；注意手臂也会碰到桌边，先把夹爪抬到桌面上方再接近。
2. 按 `3` 选择左臂、`4` 选择右臂，按住 `Z` 张开夹爪。
3. 用 `W/S`、`A/D`、`R/F` 调整位置，`U/J`、`I/K`、`O/L` 调整姿态，让物体进入两指之间。
   `Shift` 可慢调。当前默认 TCP 标记位于夹爪电机轴附近，抓取对准位置应看实际指尖间隙。
4. 按住 `X` 闭合至接触，松开仍保留夹持目标；按 `R` 抬起。按 `Z` 张开放下，`Backspace` 重置全部物体。

三个方块各重 100 g，香蕉重 120 g；这些质量和摩擦系数均为仿真假设。
物体使用自由关节和重力，靠桌面支撑、手指接触摩擦夹持，没有吸附、焊接或抓取后跟随位姿的逻辑。
手指位置伺服的单指驱动力限为 15 N，碰到物体会停止合拢；松开 `X` 后继续保持闭合目标。
香蕉使用原网格的**凸包碰撞近似**，凹曲部分不完全贴合外观，抓取时应让夹爪横跨香蕉较窄的截面。
接触参数参考 [MuJoCo 接触模型说明](https://mujoco.readthedocs.io/en/latest/computation.html)，
仅提高指尖接触阻抗以减少长期夹持滑移，未改变底盘使用的全局接触求解设置。

不打开窗口的抓取自检：

```bash
./run_keyboard_sim.sh --headless-grasp-check
```

检查四个物体在桌面稳定放置、左右夹爪各夹起方块超过 12 cm、保持 8 秒、张开后落回桌面，
以及桌外物体落地。测试通过 IK 初始化抓取前的手臂姿态，随后使用实际键盘控制路径和动力学积分；
这项自检不验证从初始垂臂姿态到抓取位置的自动避障规划。

### 躯干升降

按键参考 [HEI 的键盘仿真](https://github.com/lipengdong/hei-rebot-lift/blob/main/software/lerobot-hei-rebot-lift/examples/hei_rebot_lift/VR_mujoco_ik/mujoco_ik/hei_robot_keyboard_mujoco_sim.py)：

1. 按 `2` 选择升降模式。
2. 按住 `K` 降低、按住 `I` 抬高；松键立即保持，两个键同时按下不移动。
3. 按住 `Shift` 为 25% 慢速；`Space` 停止，窗口失去焦点也会停止。
4. 按 `3 / 4` 切回双臂，升降停在当前位置；`Backspace` 恢复完整 home。

**初始 home 已处于最高位，首次可以先按 `K` 下降，再按 `I` 抬升。**
默认肩部高度变化速度为 `0.08 m/s`，可用 `--lift-speed-m-s` 调整。
当前模型的肩部高度行程约 `0.509 m`；这是折叠连杆轨迹，伴有前后位移和躯干倾角变化，
不是 HEI 的独立垂直滑台。升降时双臂的关节角保持，随肩部一起运动。

实现使用 `link_019_joint_position` 的 `0–1.75 rad` 控制范围，以高度目标反求驱动角，
联动 `link_016_joint`，并让 `link_017/018_joint` 平分滑轨位移。
每步都检查滑轨行程与 `closure_011` 连接点误差（小于 `1 μm`）；不满足时保持当前姿态。
升降后机械臂 Pinocchio IK 使用更新后的肩部坐标系。

原 MJCF 的下转轴相对上转轴有约 `0.988°` 偏斜，会使该平面闭环无法正常折叠。
`torso_lift.py` 在内存中将 `link_016_joint` 的轴线对齐 `link_019_joint`；
原始 XML 和 home 几何位置不变。**这是仿真模型修正，不是真机轴线标定。**

### 末端参考点（夹爪开合电机轴线）

默认使用驱动两指开合的电机轴线附近的参考点。当前 MJCF 没有电机 8 的独立旋转关节，
因此依据 `hand_0.obj` / `hand_1.obj` 的圆形安装面几何估计轴线：平行于夹爪 `hand` 的
局部 Z 轴，经过局部 `(0.000001, 0.005, 0)` m。Z=0 选在 hand 原点平面，
**这不是实测的电机输出轴端面中心，精确位置仍需 CAD/实机标定**。

程序仅在内存中重定位原有空的 `hand_tcp` body，位置读数、旋转目标和 Pinocchio IK

## 当前范围

- 两臂各 7 关节，默认将 `openarm_{side}_hand_tcp` body 重定位到上述夹爪电机参考点。
- Pinocchio 计算机械臂正运动学，CasADi 构建可微目标，IPOPT 求解有约束的关节角。
  目标包含位置误差、旋转矩阵误差及关节连续性代价；每次以上一实际姿态为初值，
  最多迭代 50 次。关节限位和每帧速度限制作为优化边界。
- MuJoCo 负责读取完整 MJCF、显示机器人和检查最终位姿。
  完整 MJCF 含闭环约束，当前 Pinocchio 解析器不能直接读取，因此程序从 MuJoCo
  编译后的关节轴、关节原点和 TCP 变换提取每条 7 关节串联臂，在内存中建立 Pinocchio 模型。
  无需另存 URDF，且与 `--tcp-reference` / `--gripper-motor-offset-m` 同步。
- 求解不收敛、结果非有限、越界或位姿误差增大时，保持当前关节角。
- 多轴平移/旋转分别归一化；目标从当前 FK 增量生成，避免不可达目标持续累积。
- 初始 home 是全零，手臂接近伸直，部分方向在奇异位形处无法移动。可以先按 `Tab`，
  用 `]` 选中关节 4，按住 `=` 弯曲肘部，再按 `Tab` 回到 TCP 模式。
- 夹爪同步控制两个手指的 slide 关节，按各自模型行程开合；物理模式支持接触摩擦抓取。
- **默认是运动学预览，更新 qpos 后调用 mj_forward，不运行 mj_step 动力学。**
  该预览不求解接触动力学；物理模式也未实现自动碰撞避让，不能替代真机抓取性能验证。
- 可选 `--chassis-physics` 在内存中添加底盘和物体自由关节，启用轮地接触与桌面抓取，详见上面的实验功能说明。
- `step_torso()` 通过 `torso_lift.py` 联动 `link_016/019/017/018`，保持躯干闭环连接。
- 本次不接入 VR、相机视频回传、数据录制或策略推理。

模型配置集中在 `KeyboardSimulator.__init__()`，以后换关节名/TCP 可在此修改。
逆解实现位于 `pinocchio_ik.py`，每次启动会核对两套模型在初始姿态下的 TCP 正解。
物理模式区分轮轴力矩和上身位置目标，不会将 IK 角度直接写入所有 `ctrl`。
本模型左右夹爪执行器类型不同，物理模式在内存中统一使用手指位置伺服，默认预览仍直接更新手指位置。
