# Meta Quest 控制移动双臂仿真

电脑直接连接全达妙双臂的真机入口见 [电脑直连双臂 VR](README_VR_REAL_zh.md)，
已整合启动准备和退出回落。以下说明仍用于仿真。

参考 [HEI ReBot Lift 的 VR 仿真流程](https://github.com/lipengdong/hei-rebot-lift/blob/main/README_zh.md)，
将 Quest 双手柄的相对位姿、握把、扳机、摇杆接入当前 `mobile_openarm` 模型。
仅控制 MuJoCo，不连接电机、机器人 host 或真机命令端口。

双臂使用已有的 Pinocchio + CasADi/IPOPT 七关节逆解，升降使用已有的闭环机构求解，
底盘使用四轮摩擦、被动斜连杆和磁吸端点切换。默认启用物理底盘与桌面接触抓取。
已有 `run_keyboard_sim.sh` 仍可独立使用。

## 1. 环境

本机继续使用已有 `hei-rebot-vr` 环境。VR 额外需要 `pyzmq` 和 `websockets>=14,<17`，
以及生成本地 HTTPS 证书的 `openssl` 命令。本次开发时该环境已具备这些依赖。
启动脚本会自动激活该 Conda 环境并清除 `LD_LIBRARY_PATH`，不需要另外安装 Pinocchio。

新机器使用本目录的 `environment.yml` 创建环境；已有仿真环境缺少 VR 库时只补装：

```bash
conda activate hei-rebot-vr
python -m pip install 'pyzmq>=25' 'websockets>=14,<17'
```

可通过 `MOBILE_OPENARM_CONDA_ENV=环境名` 或 `PYTHON=/环境路径/bin/python` 覆盖解释器。

## 2. 启动头显网页

电脑和 Quest 连接同一局域网。先在电脑终端查看局域网 IP：

```bash
hostname -I
```

选择与头显同一网段的 Wi-Fi / 有线网卡地址，排除 Docker/VPN 地址。
终端 A 启动网页服务，**将下面的 `192.168.1.100` 换成你的电脑 IP**：

```bash
cd /home/xfff67/lerobot/examples/mobile_openarm
./run_vr_server.sh --hostname 192.168.1.100
```

服务首次启动在 `.vr-certs/` 自动生成自签名证书和私钥（已被 Git 忽略），
仅提供头显网页所需的 HTTPS；不修改系统信任设置。
头显浏览器访问终端打印的 `https://电脑IP:8443`。首次访问时需你自己在头显中确认本地证书提示，
再点击唯一的“Start VR”按钮并按头显提示授权。与 HEI 一样优先直接进入透视控制，
设备不支持透视时自动使用普通 VR，无需选择模式。会话运行时，同一按钮变为“退出控制”。
手机或普通电脑浏览器通常不支持 `immersive-vr`，应使用 Quest 自带浏览器。

网页无需 CDN、账号或额外 APK，直接使用 WebXR。
启动页参考本机 HEI-ReBot Telegrip 的居中布局，操作说明与诊断可展开查看。
手柄显示红 +X、绿 +Y、蓝 +Z 三个实体箭头，沿手柄局部坐标轴随手柄旋转。
原点小圆环为白色时松开、橙色时握住；箭头颜色固定，不改变控制坐标映射。
网页每个 XR 帧发送最新位姿，避免 72/90 Hz 头显被旧的 60 Hz 门限降为 36/45 Hz。
**机器人画面在电脑 MuJoCo 窗口显示，目前不向头显传输仿真相机画面**，与参考教程的纯仿真练习方式一致。
透视模式是否可用取决于设备和浏览器支持。

网页/WSS 共用 TCP `8443`；VR 数据只在电脑本机发布到 `127.0.0.1:5567`。
若页面打不开，先检查电脑 IP、同一局域网、访客 Wi-Fi/AP 隔离及电脑防火墙对 `8443` 的放行。
`5567` 不需要对头显开放。换网后需要更新地址；如需重新生成匹配新 IP 的证书，可指定新的
`--cert-dir .vr-certs/新IP`。请保留终端 A 运行。

## 3. 启动仿真

终端 B：

```bash
cd /home/xfff67/lerobot/examples/mobile_openarm
./run_vr_sim.sh
```

默认加载当前 `model/mjcf1/robot.xml`、桌面物体和物理底盘。无需启动原键盘仿真。
双臂初始姿态均为第四关节弯曲 +90°；左 X / 右 A 回位也使用这个姿态。
收到有效数据后终端显示 `tracking left=True right=True`。
先松开握把，再按住对应侧握把开始操作；启动、停止、断线或丢失追踪后均如此。

初次操作面向电脑，松开两侧握把、摇杆回中，长按右手柄 Meta 按钮约 3 秒重新居中。
重新居中会暂停输入约半秒，并要求松开握把再握住，保持 XR 会话。
更换操作位置/朝向后重复这一步。
首次只小幅移动一只手柄，确认方向。默认映射为：向前 → 模型 `−X`，向左 → `−Y`，
向上 → `+Z`，与现有键盘的 `W/A/R` 一致。
左右臂按 MJCF `openarm_left_*` / `openarm_right_*` 命名，不能用屏幕左右来判断。

## 4. 手柄操作

| 操作 | 功能 |
| --- | --- |
| 按住左 / 右握把（侧面 grip）并移动、旋转手柄 | 对应臂跟随相对位姿，可同时控制两臂 |
| 松开握把 | 对应臂停止跟随；可换一个舒服的位置重新握住，不会跳回旧原点 |
| 握把按住时按前扳机 trigger | 逐渐张开夹爪 |
| 握把按住时松开 trigger | 逐渐闭合夹爪；松开握把则保持最后开度目标 |
| 左握把 + 左摇杆上 / 下 | 升高 / 降低；home 已在最高位置，初次可先向下试 |
| 右握把 + 右摇杆上 / 下 | 沿当前轮向前进 / 后退 |
| 右握把按住、左握把松开 + 左摇杆左 / 右 | 向左 / 向右转轮（增大 / 减小轮组转角），与键盘 A / D 一致；松开摇杆保持轮向 |
| 右摇杆左 / 右 | 不绑定运动，前后行驶时偏向左右也不会改变轮向 |
| 右握把 + 右 B / 左 Y | 自动请求自转构型，然后顺时针 / 逆时针旋转；两键同时按抵消 |
| 右握把 + 按下右摇杆 | 切回平移并回正轮组 |
| 自转后右握把 + 右摇杆上 / 下，或左握把松开 + 左摇杆左 / 右 | 自动切回平移，然后行驶 / 转向 |
| 松开右握把 | 底盘制动，取消尚未完成的轮组切换 |
| 对应握把松开时按左 X / 右 A | 对应臂缓慢回到仿真工作初态（第四关节 +90°），夹爪保持；重新握住可中断 |

**底盘行驶与轮组转向分在两个摇杆：右摇杆上下行驶，左摇杆左右调整轮向，不是即时横移。**
底盘操作保持右握把按住、左握把松开；此时左摇杆上下不触发升降。
按住左握把后，左摇杆上下控制升降，左右不再控制轮向，避免斜推摇杆时升降与转轮同时动作。
两个摇杆可同时操作，边转轮边沿当前实际轮向前进 / 后退。要横移，将轮向调整到约 ±90°。
切换平移/自转需持续握住右握把并等待数秒，终端显示 `magnetic endpoint reached` 后才能行驶。
自转时保持 B/Y，直到切换完成并开始旋转；松开 B/Y 停止旋转，但保留自转构型。
停止后的机械滑动、转向和切换都由物理模拟完成，不直接改写底盘自由关节或轮角。

在电脑仿真窗口获得焦点时：

| 按键 | 功能 |
| --- | --- |
| Space | 停止输入并取消复位/切换；松开后仍需松握把再握住 |
| Backspace | 整机和场景恢复初始状态，然后重新握持 |
| V / C | 开关坐标系 / 接触点显示 |
| Esc | 退出仿真 |

窗口失焦也会停止并要求重新握持。VR 入口不接受原来的键盘运动键，避免两个控制源争用。
鼠标视角操作不变。使用 VR 入口时底部旧键盘类的初始化日志仅说明复用的 IK/模型，
实际操作以启动时的 `VR:` 提示和此表为准。这里未接入数据集录制快捷键。

### VR 中的手柄和位姿显示

参考 HEI `telegrip/web-ui`：显示与其 A-Frame `oculus-touch-controls` 相同的
Touch 手柄模型，按输入设备类型选择 Quest 2、Touch Plus 或 Touch Pro。
模型及纹理由本地 HTTPS 服务提供，头显无需访问外网；未知型号使用 Quest 2 外观。
保留随手柄转动的红 X / 绿 Y / 蓝 Z 正向箭头。

视野下方按 HEI 样式显示两行居中文字：`Head Pos`（XYZ，米）、`Head Rot`（XYZ 欧拉角，度），
背景完全透明，没有深色底板。网页上的位姿信息另保留左右手柄坐标。
按下扳机时，对应手柄模型的扳机部件变为 HEI 的亮蓝色 `#22DDFF`，松开恢复；
握把、摇杆按下和 A/B/X/Y 也使用相同的按键高亮。
文字每秒刷新 10 次，手柄模型及控制数据仍按 XR 帧率更新。
坐标相对 `local-floor` 地面参考系，重新居中后数值会改变。
重新居中等待松握把时仍可看到手柄；模型显示不代表机器人控制已恢复。
跟踪丢失显示“未追踪”，退出会话后清除网页上的旧坐标。

更新涉及网页服务新增模型路由：重启 `run_vr_server.sh` 后，在头显刷新页面再点 `Start VR`。

## 5. 控制行为与调节

- 默认 TCP 为两根手指前端之间的中心，与 HEI 的控制点含义一致。
  按本模型指尖网格定位到 `hand` 局部 `(0.000001, 0.006, 0.095501)` m，黄色小球标记该点。
  原地旋转手柄时，IK 尽量保持这个抓取中心的位置并改变夹爪朝向。
  可用 `--tcp-reference gripper-motor` 切回旧电机轴参考点，或 `--tcp-reference model` 使用原 XML 点。
- 握持时以当前手柄和当前 TCP 建立相对原点；TCP 目标保存在肩部坐标系，底盘/升降会带着手臂一起移动。
- 默认位移倍率为 1；TCP 平移/转动及关节变化均限速，IK 保留原模型关节限位与失败保持机制。
  手柄移动太快时，握住期间机器人会限速追赶目标；松开握把立即取消该目标。
- 伸直附近达到可达边界时，不再积累继续外推的目标分量；手柄回拉即可重新弯肘，
  无需先退回整个越界距离。边界处会调整相对位置原点，沿边界运动和姿态目标仍保留。
  普通速度限制引起的跟随滞后仍会继续追赶；原有关节限位和每步速度限制保持生效。
- VR 使用独立仿真限速：末端 `0.5 m/s`、旋转 `180°/s`、关节 `3 rad/s`。
  参考 HEI 的目标自适应滤波，快速移动时约 `18 ms`、静止附近约 `55 ms` 时间常数。
  键盘入口仍使用原来的 `0.12 m/s`、`35°/s`、`1 rad/s`；这些参数不是实机电机规格。
- 每侧超过 `0.3 s` 没有有效位姿、NaN/无效四元数、丢失追踪或网页退出 XR 时禁用该侧。
  不继续使用旧摇杆或旧握持状态；追踪恢复后需要松开再握住。
- 相邻有效帧位移超过 `0.25 m` 或旋转超过 `75°` 会停用该侧，避免追踪突然重定位带来的大动作。
- 断流取消自动复位；Space/失焦会取消两臂复位和底盘切换。物理模式仍会产生正常的接触与制动过程。
- 夹爪沿模型行程逐渐开闭，保持物理接触抓取，未添加 TCP 物体吸附。模型动力学仍为原有实验设置。

例如降低手部移动倍率和关节速度：

```bash
./run_vr_sim.sh --vr-position-scale 0.6 --joint-speed-rad-s 0.6
```

只验证双臂/升降的运动学跟随，不计算底盘和抓取物理：

```bash
./run_vr_sim.sh --no-chassis-physics
```

还支持 `--mjcf`、`--plain-scene`、`--tcp-reference` 等原仿真参数。
`--vr-forward-yaw-deg 180` 为默认机器人前方；如使用其他模型朝向可修改此角度。

## 6. 已有参考项目 Telegrip 时

可以继续运行参考项目的 `run_telegrip.sh`，头显进入它的网页，然后仅启动本项目的仿真：

```bash
./run_vr_sim.sh --vr-endpoint tcp://127.0.0.1:5567 --vr-topic vr_data
```

此时不要再运行本目录的 `run_vr_server.sh`，以免占用同一端口。
默认兼容单帧字符串 `vr_data {JSON}`，包含 `leftController` / `rightController`、
`position`、`quaternion`（字段 x/y/z/w）、`gripActive`、`trigger`、`thumbstick` 和 A/B/X/Y 按钮字段。
订阅端只保留最新消息，不回放排队的动作；使用纯 JSON 发布器时传 `--vr-topic ''`。

## 7. 无头显自检

如果进入透视后只能看到外界，先在电脑观察机器人是否跟随手柄；透视本身不是连接成功的依据。
网页会显示 XR 阶段、帧计数和每侧手柄状态；网页服务终端打印 `[VR browser]` 状态变化。
同一电脑也可在浏览器查看 `https://电脑IP:8443/api/status`：
`page_ready_click_enter` 表示仍在网页，`requesting_xr_permission` 表示等待头显授权，
`xr_running` 表示 XR 帧循环运行；`no_grip_pose` / `no_gamepad_use_controllers` 表示未取得手柄位姿/实体手柄。
摘下头显或打开系统菜单可能使 XR 暂停；排查时请佩戴头显并关闭系统菜单。
状态诊断消息不会刷新或生成机器人运动输入。

```bash
cd /home/xfff67/lerobot/examples/mobile_openarm
./run_vr_sim.sh --no-chassis-physics --headless-check
./run_vr_sim.sh --headless-check
./run_vr_python.sh check_vr_transport.py
node check_vr_web.cjs
```

检查包括协议校验、每侧超时、双臂位移/旋转、重握无跳变、夹爪、升降、复位、停止、
追踪跳变、物理底盘前进/转向/自转切换，以及 HTTPS → WebSocket → ZMQ 完整链路。
网络测试仅短暂监听 `127.0.0.1` 随机端口，使用临时证书并自动清理。
最后一项使用 Node.js 的 WebXR 桩验证网页会话生命周期、按钮映射、追踪丢失和退出控制；不需要安装 npm 包。
这些测试不代表已经用你的 Quest 真机联调；头显浏览器兼容性、实际追踪和手感仍需上手确认。
